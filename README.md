# אוצר מילים מוגבל

> מתוך חוברת C – שאלות לחזרה (עמ' 109).

## המשימה

כידוע, אנגלית היא שפה עשירה ובה הרבה מילים. כאשר כותבים באנגלית קשה מאוד לכתוב משפטים בהם גיוון המילים הוא גדול, ולכן קורה שמילה או מספר מילים חוזרות על עצמן יותר מפעם אחת בקטע טקסט.

עליך לבנות תוכנית שמקבלת בשורת הפקודה (באמצעות `argc` ו-`argv`) שני קבצים:

1. קובץ טקסט המכיל קטע באנגלית.
2. קובץ אוצר מילים, המכיל מילים ועבור כל מילה שמופיעה בו מכיל מילה נרדפת אחת או יותר.

המטרה – טיילו ברחבי קובץ הטקסט (הקובץ הראשון) והחליפו בו כמה שיותר מילים במלים נרדפות מתוך קובץ אוצר המילים. כמובן, שכאשר אין למילה בקובץ הטקסט מילים נרדפות, יש להניח לה לנפשה ולהשאירה בטקסט.

לדוגמא, אם קובץ אוצר המילים מורה להחליף את המילה `drink` במילה `beverage`, המשפט הבא:

```
There's a bar in Hawaii where they sell some unique drink
```

יהפוך ל:

```
There's a bar in Hawaii where they sell some unique beverage
```

## הגדרות מדויקות (לצורך הבדיקה האוטומטית)

בחוברת המקורית את פורמט קובץ אוצר המילים בוחרים בעצמכם. כאן הפורמט קבוע, כדי שאפשר יהיה לבדוק אוטומטית.

**הרצה**

```bash
./build/thesaurus <text-file> <thesaurus-file>
```

הטקסט אחרי ההחלפות מודפס ל-**stdout**. התוכנית לא משנה את הקבצים.

**פורמט קובץ אוצר המילים**

```
drink beverage refreshment
big large huge
dog hound
```

- כל שורה: מילה, ואחריה המילים הנרדפות לה, מופרדות ברווחים או בטאבים (אחד או יותר).
- מחליפים תמיד במילה הנרדפת **הראשונה** בשורה.
- שורה ריקה, או שורה עם מילה בלי מילים נרדפות – מתעלמים ממנה.
- אם אותה מילה מופיעה בכמה שורות – השורה **הראשונה** קובעת.

**מהי מילה בטקסט**

- מילה = רצף מקסימלי של אותיות אנגליות (`A-Z`, `a-z`). כל תו אחר (רווח, פיסוק, ספרה, גרש, מקף, `_`) מפריד בין מילים.
  לכן ב-`There's` יש שתי מילים: `There` ו-`s`.
- החלפה רק של **מילה שלמה** ורק בהתאמה **מדויקת**, כולל אותיות גדולות/קטנות: `drink` מוחלף, `Drink` / `drinks` / `drinking` לא.
- כל מה שאינו מילה מועתק לפלט **בדיוק** כמו שהוא, תו אחרי תו (כולל `\r`, טאבים, ושורה אחרונה בלי `\n`).
- מעבר אחד בלבד: מילה שהוכנסה כהחלפה לא מוחלפת שוב.

**גבולות**

- אין הגבלה על אורך מילה, אורך שורה, גודל הטקסט או מספר המילים באוצר המילים. בבדיקות יש מילים של אלפי אותיות, טקסט של כ-1.5MB ואוצר מילים של 20,000 מילים. כלומר: הקצאת זיכרון דינמית, לא מערכים בגודל קבוע.
- כל בדיקה מוגבלת ל-10 שניות. חיפוש לינארי באוצר המילים עבור כל מילה בטקסט עלול להיות איטי מדי. חשבו על `qsort` + `bsearch`.

**שגיאות**

- מספר ארגומנטים שגוי, או קובץ שלא ניתן לפתוח: הודעת שגיאה ל-**stderr** וקוד יציאה `1`.
- הצלחה: קוד יציאה `0`.
- כל זיכרון שהוקצה משוחרר, וכל קובץ שנפתח נסגר.

## איך עובדים

```bash
make                       # קימפול ל-build/thesaurus
make test                  # כל הבדיקות
make asan                  # הבדיקות עם AddressSanitizer
tests/run_tests.sh 02_several_words   # בדיקה אחת
./tests/grade.sh -v        # הציון שתקבלו, עם פירוט כישלונות
```

כל בדיקה היא תיקייה ב-`tests/cases` עם `text.txt`, `thesaurus.txt` ו-`expected.txt` – אפשר לפתוח ולראות בדיוק מה מצופה.
מותר לחלק את הקוד לכמה קבצי `.c` / `.h` בתוך `src/`.

## הגשה

- כל `git push` מריץ את הבדיקות אוטומטית. את הציון רואים בלשונית **Actions** של המאגר שלכם ← הריצה האחרונה ← **Summary**.
- ✅ ירוק = 100. ❌ אדום = חלק מהבדיקות נכשלו – הטבלה ב-Summary מראה אילו.
- הציון שנספר הוא של ה-push האחרון לפני הדדליין.
- **אסור לשנות** את התיקיות `tests/` ו-`.github/`. מאגר שבו הן שונו מסומן אצל הסגל.
